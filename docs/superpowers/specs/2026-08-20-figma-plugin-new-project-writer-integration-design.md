# Figma 插件通用 Writer 产品接入设计

## 目标

让设计师在现有 Figma 插件中，从当前选择直接生成并下载 FairyGUI 6.1.4 新工程 ZIP。
新建流程使用已经验收的通用 `mapping → UIR → FGUI Plan v2 → NewProjectManifest → XML → ZIP`
链路，不再通过模板工程绕行。

本阶段只接 Figma 插件。Web Console 不改。村庄升阶继续只作为通用回归样例，生产代码和配置不得包含
村庄页面或节点特例。

## 产品工作流

### 默认界面

插件默认只呈现一个任务：把当前 Figma 选择生成 FairyGUI 新工程。

界面采用 360px 单列布局和 8px 间距网格，所有内容共享 16px 左右边距。默认可见内容按顺序为：

1. 插件标题与更多菜单。
2. 当前选择摘要：名称、图层数、资源数和抽象蓝图缩略图。
3. 工程名称输入框。
4. 只读状态：FairyGUI 6.1.4、新建独立工程。
5. 折叠的“生成设置”。
6. 唯一主操作“生成候选工程”。

不再显示四步流程、模板选择、版本下拉框、目标平台下拉框或默认可见的模式切换。

### 更新已有工程

“更新现有工程”不删除，但从默认流程移入右上角更多菜单。进入后继续使用现有 ZIP 上传、工程绑定和更新
链路。本阶段不重构 Project Binding，也不把它引入新建工程 Writer。

### 生成、审核与状态反馈

底部操作区原地承载状态，不跳转页面：

- 空闲：`生成候选工程`。
- 导出选择：按钮禁用，显示 `正在读取当前选择`。
- 转换和校验：显示阶段标签与进度。
- 待审核：切换到分类型审核工作区；候选 ZIP 仍不可下载。
- 已批准：开放 `确认并下载 ZIP`；首次点击触发下载，之后可 `再次下载`。
- 已退回：废弃候选，返回选择与命名状态。
- 失败：按钮上方显示一条稳定、可行动的公开诊断，并提供 `重试`。

刷新选择会清除旧结果和错误，重新计算选择摘要。生成期间锁定选择相关控件，避免请求内容与界面状态漂移。

### 分类型审核工作区

审核沿用既有 Designer Review 的对象分类，但适配新建工程：

- 图片审核：Figma 原图与 Writer 导出图片并排对比，并显示尺寸、裁切、九宫格和透明度结果。
- 组件/界面审核：有可信渲染图时显示视觉对比；没有渲染图时显示层级、几何、文字和组件引用的结构化摘要，
  不伪造视觉预览。
- Package/资源审核：显示组件和资源新增清单、引用闭包、命名冲突与完整性检查。
- 统一检查：以设计师可理解的文案汇总结构、资源、Writer 门禁、警告和阻断问题。

审核决策作用于完整候选工程。用户不能逐文件勾选，因为 package 描述、组件 XML 和资源必须保持闭包一致。
存在任一 `ERROR` 时禁止批准；警告必须明确展示并由用户整单确认。退回会使候选失效，不能继续下载。

## 架构

### 插件 UI

`ProjectWorkflowPage` 拆分为清晰的模式外壳和新建 Writer 面板：

- `NewProjectWriterPanel`：默认新建流程和候选生成状态。
- `NewProjectReviewPanel`：图片、组件/界面、Package/资源审核与整单决策。
- `ExistingProjectUpdatePanel`：封装现有更新流程。
- `PluginModeMenu`：在两者之间显式切换。

新建面板不请求模板选项。FairyGUI 版本由新建 Writer 合同固定为 `6.1.4`。目标平台如果仍是服务端必需字段，
由受版本控制的默认配置提供，而不是要求用户重复选择。

### 插件客户端合同

新增独立的新建 Writer 客户端方法。输入只包含：

- 当前选择的 `SelectionManifest`；
- 选择中声明的资源 bytes；
- 经客户端初步约束、服务端再次验证的工程名称；
- 可选的、闭合且版本化的生成设置。

它不包含 `templateId`、已有工程 ID、已有资源 ID 或 Project Binding 数据。

响应包含：

- 下载文件名；
- ZIP bytes；
- SHA-256 与大小；
- 稳定、公开的诊断；
- 完成阶段。

候选生成响应只返回审核 ID 和公开摘要，不直接返回 ZIP bytes。审核通过后，下载入口才返回已经验证的候选 ZIP。

### 服务端入口

新增专用 API 入口处理插件新建 Writer 请求。入口复用现有上传限额、身份验证、隐私边界和公开错误适配，
并按以下顺序执行：

1. 验证选择合同与资源闭包。
2. 应用通用组件映射并编译 UIR。
3. 验证 UIR 并编译 FGUI Plan v2。
4. 验证 Plan bindability 与资源 payload。
5. 编译、验证 `NewProjectManifest`。
6. 生成并重开验证 FairyGUI XML、工程目录和确定性 ZIP。
7. 生成不可下载的候选记录和分类型 Designer Review。
8. 用户整单批准后才发布下载能力；退回则废弃候选。

旧的模板新建 API 暂不删除，以免无关消费者回归；Figma 插件不再调用它。

## 错误与安全边界

- 选择变化、空选择、资源超限、路径问题、组件定义缺失、能力不支持和 Writer 校验失败全部 fail closed。
- 任何失败都不得发布半成品 ZIP。
- 未审核、含阻断错误、已退回或已失效的候选均不得下载。
- 审核预览必须标注证据类型；结构化摘要不得冒充 FairyGUI 渲染结果。
- 公开错误只使用稳定 code、用户可执行的 message 和有限 evidence；不回显本地路径、资源 bytes、异常链或环境值。
- 缺少组件定义时不按名称猜测组件，也不为村庄样例添加例外。仅允许已批准的安全 raster fallback。
- 新建链路不读取、扫描或修改已有 FairyGUI 工程。
- 下载产物沿用 Writer 的单文件/合计资源限额、隔离图片探测、确定性 ZIP 和原子发布保证。

## 测试与验收

### 自动化

- 插件 UI：默认单屏布局、选择摘要、工程名、控件锁定、进度、错误、待审核、批准、退回和再次下载。
- 审核 UI：图片、组件/界面、Package/资源三类视图，统一检查，阻断批准，警告确认和整单决策。
- 模式隔离：更新流程只能从更多菜单进入，新建请求不携带模板或 Project Binding 字段。
- 插件客户端：请求/响应严格合同、取消、超时、公开错误和下载文件名。
- 服务端 API：认证、限额、输入闭包、转换链路、Writer 候选、审核状态机和所有失败/未批准不发布。
- 端到端：真实通用选择资源生成可被 Writer archive validator 重开的 ZIP。
- 回归：村庄样例继续在缺少完整组件定义时以通用诊断阻断，生产代码/配置无样例特例。
- 原有更新工程与 Web Console 测试保持通过。

### 真实验收

在开发版 Figma 插件中完成一次：

1. 选择一个中立、可生成的 Figma frame。
2. 确认选择摘要与工程名称。
3. 点击 `生成候选工程`。
4. 分别检查图片、组件/界面、Package/资源审核内容和统一检查结果。
5. 整单批准并点击 `确认并下载 ZIP`。
6. 确认下载文件名、成功状态和再次下载。
7. 用 FairyGUI Editor 6.1.4 打开下载工程并保存、关闭、重开。

验收证据包含插件关键状态截图、下载文件哈希、ZIP 重开结果和 FairyGUI Editor transcript。若桌面截图接口不支持，
必须如实记录，不得用证据卡冒充真实应用截图。

## 不在本阶段范围

- Web Console 接入或视觉调整。
- 重构或扩展 Project Binding。
- 更新已有工程的语义、资源复用或冲突策略。
- 新增 FairyGUI 能力范围。
- 村庄升阶专用逻辑。
- 多版本 FairyGUI 或让用户选择 Writer dialect。

## 验收标准

- 用户在插件默认界面内只需确认选择并填写工程名即可生成候选；完成分类型整单审核后才可下载新工程 ZIP。
- 图片、组件/界面、Package/资源三类审核和统一检查均有真实、可追溯证据；无渲染能力时明确降级为结构化摘要。
- 新建插件请求实际走通用 Writer，不再依赖模板工程。
- Writer 的五道校验、确定性、安全和隐私边界未被产品接入绕过。
- 更新现有工程仍可从更多菜单使用，行为不回归。
- Web Console 无功能或界面变化。
- 自动化回归与真实插件/FairyGUI 验收均有可审计结果。
