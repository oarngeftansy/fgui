# 独立 PSD → FairyGUI 替换应用实施计划

## 目标

交付一个只依赖本机服务和浏览器界面的独立应用。每次任务必填旧 FairyGUI 工程、目标目录与根组件、PSD；两个固定字体由应用自动校验；外部 PNG 与效果图均为可选输入。PSD 不经过 Figma，直接进入 HIFI 中间模型、映射、候选、审核和交付。

## 工作流

1. 打开本地应用。
2. 导入旧 FairyGUI ZIP，选择目标目录和根组件。
3. 导入 PSD；自动检查固定字体、画布、图层类型和无损阻断项。
4. 将 PSD 转为带稳定图层身份的 HIFI-IR。
5. 盘点旧组件和 HIFI-IR，逐项确认映射。
6. 生成候选工程，展示对象和文件差异。
7. 通过视觉门禁及 FairyGUI Editor 检查后下载正式 ZIP。

## 任务

### Task 1：独立应用准备页（已完成）

- 将 Web Console 首页改为本地 HIFI 替换应用。
- 复用旧工程上传、目标树和 PSD 流式检查。
- 新增本地启动凭据引导，Web 页面不依赖 Figma 插件。
- 自动校验两个固定字体的文件哈希；字体与切图不作为必填上传项。

### Task 2：持久化 PSD 来源和 HIFI-IR（已完成）

- PSD 上传一次后按 SHA-256 保存。
- 提取图层 ID、父路径、顺序、边界、可见性、文字和视觉类型。
- 将智能对象、调整层、效果和蒙版记录成显式能力项。

### Task 3：直接映射到旧 FGUI

- 让现有映射器消费 HIFI-IR。（已完成）
- 复用目标组件保护、映射决策会话和候选工程门禁。（映射已完成，候选仍受无损门禁阻断）
- 提取 PSD 文字运行的字体、字号、颜色、行距、字距、变换与段落对齐。（已完成；主页 10 个可见文字层全部解析为固定字体 `CoreSansESW01-55Medium`）
- 结构化提取颜色叠加、描边、阴影、发光等图层效果的启用状态与关键参数。（已完成；主页可见图层识别到 32 个启用效果，其中可见文字为 10 个颜色叠加和 4 个描边）
- 按字体文件 SHA-256 将 PSD 字体精确绑定到旧工程的 FairyGUI `ui://` 字体资源，并写入有效字号、颜色叠加、外描边、字距、行距、粗斜体与对齐。（已完成；主页 Core Sans 精确命中 `ui://ub7gxzj7kdwnp`）
- 对被采用的 PSD 像素、形状和智能对象图层按需生成内部 RGBA PNG 资源；用户不需要额外提供切图。（已完成；主页 68 个有面积的可见视觉图层可由本地解析器合成）
- 外部切图只作为可选覆盖资源。

### Task 4：无损验证与真实交付

- 提取 PSD 内嵌合成图作为审核基准。（已完成）
- 独立应用接入候选生成、对象/文件差异审核、Editor 三项检查和正式 ZIP 下载。（已完成；有无损阻断时保持锁定）
- 无损阻断允许生成和下载审核候选，但会令候选不可批准，并继续锁定正式 ZIP；隐藏图层不再制造与最终画面无关的阻断。（已完成）
- 大型 FGUI 工程的包、目录和根组件按层级折叠选择，避免一次展开全部资源。（已完成）
- 对比 PSD 合成图、候选组件渲染和可选效果图。（等待 FairyGUI 候选渲染器）
- 首先跑通主页 PSD → `Tower / Panel / Panel_Tower_Main`。
- 再覆盖其余十份 PSD，并记录各类阻断或等价转换证据。

## 验收原则

- 两个固定字体存在且哈希匹配时不要求用户上传字体。
- 外部切图和效果图缺失不阻止普通 PSD 解析。
- 任何未证明等价的 PSD 属性都会阻止正式交付。
- 不产生或依赖 Figma 文件、节点或插件消息。
